# THE RESOLVED VERSIONS OF THIS PACKAGE'S DEPENDENCY TREE, LOCKED.
#
# `pyproject.toml` declares what this package NEEDS and deliberately does not
# pin it: a library that pins its dependents' versions is a library that cannot
# be installed beside anything. This file is the other half — what an INSTALL
# resolved to — and it is passed to pip with `-c` by the three places that
# install this package into an environment somebody depends on: the required
# `validate` job, the DB-backed `runtime` job, and the runtime image.
#
# WHY IT EXISTS: SonarCloud `githubactions:S8544` / `docker:S8544`, "using
# dependencies without locking resolved versions is security-sensitive", on
# `.github/workflows/validate.yml` and `deploy/compose/Dockerfile` — a quality
# gate that is ADVISORY on this repository, registered on openDox-code#26 and
# built here. An unlocked install is a supply chain that can change under a
# green check: the same commit, tested twice, is two different programs.
#
# MEASURED, NOT WRITTEN BY HAND. Regenerate it in a clean virtual environment
# on the platform CI uses (cpython 3.12, linux) and commit the diff as its own
# act, so the change of a dependency is a change somebody reviewed:
#
#     python3 -m venv /tmp/lock && /tmp/lock/bin/python -m pip install \
#         --only-binary :all: -e ".[runtime,test]"
#     /tmp/lock/bin/python -m pip freeze --exclude-editable | sort \
#         > constraints-cpython312-linux.txt
#
# A CONSTRAINTS FILE AND NOT A REQUIREMENTS FILE: it pins what is installed and
# installs nothing itself, so the required job still installs `.[test]` alone —
# the entries for FastAPI and psycopg simply do not apply there — and the image
# still installs `.[runtime]`. One file, three installs, no second list of
# names to drift.
#
